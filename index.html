Research SystemClosed loop

Most people pick one layer. I built the loop.

A benchmark tells you where the gap is. A trace tells you what the kernel actually did. A cycle-accurate simulator tells you why the cycles went missing. Only then can an architecture close the gap — and the same benchmark proves it did. Each stage below is a shipped artefact, and each one feeds the next.

ArchitectureDCO · LCM · LLAMCAT

A shared cache that knows what a tensor is.

AI accelerators lean on software-managed scratchpads: fast, but they need explicit data movement, they fragment, and they take hours to compile for an LLM. Worse, they handle mixed-precision quantisation and quadratic KV growth badly. My bet is the other way — a managed shared cache, plus a small hardware unit that tells it what the compiler already knew.

Fig. 2 — managed shared-cache SoC with the TMUDCO (IEEE TC) · LCM (ICS '24)
Predictive policiesOne priority score, three decisions
Policy 01

Dead-block prediction

The dataflow says a tile will be read exactly n times. On access n it is finished — retire it now, rather than waiting for LRU to notice it went cold.

Policy 02

Self-adaptive anti-thrashing

Low tag bits become a uniform priority score. The lowest tier is sacrificed so a hot subset survives — and the number of tiers shrinks automatically as the cache does.

Policy 03

Coordinated dynamic bypassing

Bypass reads the same priority score as replacement, so the two never fight. Low-value traffic goes straight to DRAM and leaves the reusable working set intact.

DCO — Dynamic Cache Orchestration for LLM Accelerators through Predictive Management

Z. Zhou, C. Lai, Y. Gu, W. Zhang  ·  IEEE Transactions on Computers

The compiler already knows the dataflow; the cache throws it away. DCO feeds tensor- and tile-level metadata into replacement, dead-block prediction and bypassing, so a shared system-level cache behaves like a scratchpad — without the scratchpad's compilation cost.

Sim-FA — A GPGPU Simulator Framework for Fine-Grained Asynchronous Pipeline Analysis

Z. Zhou, Y. Gu, C. Lai, Y. Wang, W. Zhang

Hopper made FlashAttention-3 fast with TMA, WGMMA and warp specialisation — and made every academic simulator wrong. Sim-FA models those asynchronous producer/consumer pipelines cycle by cycle, with a Python companion that explains why roofline models systematically under-count DRAM traffic.

5.7% MAPE vs. real H800 (12.7% worst case) first academic sim. of TMA / WGMMA / warp spec. ablation: 64.3% error without the XOR L2 hash validated against Nsight on Blackwell arXiv:2605.00555 ↗
ICPP '252025

LLAMCAT — Optimizing Large Language Model Inference with Cache Arbitration and Throttling

Z. Zhou*, C. Lai*, W. Zhang  ·  54th Int'l Conference on Parallel Processing

During LLM decoding the last-level cache stalls not because it is too small, but because it runs out of MSHRs — the slots that track outstanding misses. LLAMCAT pairs MSHR- and load-balance-aware arbitration with two-level multi-gear thread throttling, the first work to target decode-specific miss-handling contention.

1.10 – 2.11× speedup 1.26× where miss-handling throughput binds — baselines regress 1.58× when capacity is constrained too hybrid trace-driven + analytical simulation ACM DL ↗ arXiv:2512.00083 ↗

LCM — LLM-focused Hybrid SPM-cache Architecture with Cache Management for Multi-Core AI Accelerators

C. Lai*, Z. Zhou*, A. Poptani, W. Zhang  ·  Int'l Conference on Supercomputing, Kyoto

AI accelerators lean on software-managed scratchpads that are fast but brutal to compile for — a bad trade when the workload changes every quarter. LCM takes the other bet: a shared hardware cache with LLM-aware management, and shows the software simplicity is very nearly free.

Y. Du, Y. Hu, Z. Zhou, Z. Zhang  ·  ACM/SIGDA Int'l Symposium on FPGAs

Sparse matrix–vector multiply is bound by memory, not arithmetic. HiSparse pairs an HBM-friendly sparse format with a banked-and-replicated on-chip buffer and a split-kernel floorplan that finally closes timing across dies. Work done as a research assistant at Cornell with Prof. Zhiru Zhang.

DFAC — Dataflow-Aided Intra-cluster Coalescer for AI Accelerators

C. Lai, Y. Wang, Z. Zhou, W. Zhang, R. Chang, H. Yao  ·  32nd Asia and South Pacific Design Automation Conference

The same compile-time knowledge, one level further up. DFAC carries reuse counts into hardware merge tables inside the cluster, so redundant requests collapse before they ever reach L2 — which removes round-by-round thrashing and takes the pressure off NoC bisection bandwidth.
